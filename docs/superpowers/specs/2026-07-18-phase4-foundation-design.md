## Decisions made in this session

1. **Slice scope:** M0 (scaffold, theme, auth, tab shell) + M1 (SQLite wiring, repository seam, parity test, grep guard) + the six pure sync modules. Nothing else.
2. **Reuse strategy:** fresh `create-expo-app` scaffold in the WorkLog repo root; PunchLog modules are ported file-by-file as each stage needs them. No wholesale clone, no shared-package extraction.
3. **Dev backend:** local Supabase stack in `jobsight-backend` (`supabase start`) with the Phase 3 migrations and seeded demo `super` account. Production is not touched during this slice.
4. **Build order:** pure-sync-early (Stage 1 tooling → Stage 2 pure sync → Stage 3 M0 UI → Stage 4 M1 data layer). The work plan (§C.2) explicitly marks the pure modules parallel-safe ahead of M1.

## Out of scope

Report screens and section sheets (M2), native sync adapters and lifecycle RPC wiring (M3), photos (M5), carry-forward (M6), PDF (M7), voice (M8), weather (M9), history (M10), rollups/branding/distribution (M11), account deletion (M12). Invite acceptance is deferred to M2 per P2-9. The two open product decisions (distribution-list scope, lock grace window) do not block this slice and stay open.

## Stages

### Stage 3 — M0 UI

### Stage 4 — M1 data layer

- Port `src/db/open.native.ts` and `rows.native.ts`; run `schema.ts` migrations via `PRAGMA user_version`.

The backend column map is a checked-in reference file regenerated by a script from the sibling `jobsight-backend` clone, so CI does not require the other repo. This is the test class that caught the Phase 3 `width`/`height` mismatch — it is the slice's keystone test.

**Gate:** parity test green · grep guard returns nothing · `tsc --noEmit` green.

## Error handling posture

Sync failure semantics are inherited from PunchLog, not invented: every failure path ends in retry, park-with-surface, or user decision — no silent drops. The pure tests encode these invariants before any native adapter exists. Auth errors reuse PunchLog's error-surface patterns.
